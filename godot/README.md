# 荒年 · 网页试玩

基于 2026-10-05 Windows 试玩包的原始游戏内容，使用 Godot 4.7.2 官方单线程 Web 运行时。

## GitHub Pages

发布来源：main 分支，根目录 /。`.nojekyll` 保证直接发布静态文件。

在线试玩：https://hyperlios.github.io/dearth-playtest/godot/
本目录部署在仓库的 `godot/`，根目录的旧版网页保留。

全部游戏文件使用相对路径，兼容 GitHub Pages 的仓库子路径。
首次加载约 110 MB，建议使用 Wi-Fi；iPhone 横屏、Safari 打开。
iPhone 自动启用横屏手机界面：44 px 主按钮、独立抽屉、可滚动详情与中文字体。已通过桌面触摸模拟和 WebKit 检查，仍未完成 iPhone 真机验收。

## 文件说明

- `index.html` / `loader.js`：加载页面、触摸说明、竖屏提示。
- `godot.js` / `godot.audio*.js`：官方 Godot 网页运行时。仅替换 Wasm 下载入口以读取压缩分片。
- `assets.json` / `pack-*.bin` / `wasm-*.bin`：SHA256 校验清单与压缩资源片段。片段最大 8 MiB。
- `licenses/`：Godot 与字体第三方许可。

原始游戏包内容未改动；只有浏览器窗口模式与触摸模拟兼容设置。
加载层另含 Godot 4.7.2 索引缓冲上传兼容修正：通过 WebGL2 COPY_WRITE_BUFFER 更新索引数据，并保留原有绑定，避免 ARRAY_BUFFER 类型冲突。浏览器绘制告警与绑定/数据读回均已验证。
GitHub Pages 托管的是游戏网页，朋友无需 GitHub 登录或安装 Godot。


## iPhone 适配补丁（2026-10-10）

- `mobile.pck`：只包含手机 UI 补丁及原试玩版 UI 基类，原始 Windows PCK 和规则不变。
- `mobile-src/ui.gd`：大按钮、资源栏、商店/种子/温室抽屉、种子点选、滚动模态、手机取景。
- `mobile-src/boot.gd` / `boot.tscn`：通过 `override.cfg` 指向启动场景，替换展示层；发行版不依赖编辑器专用的 `--script` 参数。
- `mobile-src/baseline_ui.gdc`：从 2026-10-05 原始 PCK 提取的 UI，保持本次试玩版本一致。不要直接混入当前桌面主工程的新规则/UI。
- `mobile-src/build.gd`：在本目录执行 Godot `--headless --path . --script mobile-src/build.gd` 可重建补丁。
- 不使用系统字体来渲染正式 UI；加载包内 NotoSansSC，特殊导航符号用中文按钮代替。
- Safari 安全区由页面留白处理；Godot 的逻辑坐标跟随实际内容区，像素密度最多 2 倍。
- 通过 `?qa=1` 可读取 `window.dearthQA` 的只读几何与缺字诊断；不提供改变经济/进度的接口。

原有桌面玩法与存档路径保留。当前仍为横屏试玩，未完成真机性能和完整 40 夜验收。

### 横屏比例修复（2026-10-10，加载器 v4）

- 根因复现：安全区域改变但没有 `window.resize` 时，CSS 750×369、画布仍为 1688×780；横纵缩放比变成 1.064738，逻辑视口也错误扩展到 798×369。
- 现在通过 `ResizeObserver` 观察实际容器，加载前后、回到页面时同步；Godot 每次读取逻辑宽高前也会同步画布，避免两套尺寸脱节。
- 修复后同一场景为 CSS 750×369、画布 1500×738、逻辑视口 750×369，横纵缩放比为 1。
- WebKit / DPR 3 模拟覆盖首次横屏、无窗口事件的安全区变化、竖屏再横屏；真实 iPhone 仍待用户验收。

### Safari 中断恢复（2026-10-10，加载器 v5）

- 症状：Safari 回到网页「开始加载」页。尚无 iPhone 崩溃日志，不能认定为某个脚本异常；页面被回收/重载是当前排查方向。
- 加入按 SHA256 索引的资源分片缓存。首次下载后重进复用本地 113,193,612 字节（约 108 MiB）；损坏片段单独重下。缓存受浏览器存储策略影响，无法保证永不被清理。
- 小型 Service Worker 缓存启动页面、引擎脚本、清单和手机补丁，完整缓存后可离线重新进入。缓存写入失败不阻止在线试玩。
- 手机画布倍率从最高 2 降到 1.5（像素数减少 43.75%），保留原安全区/横竖屏比例同步逻辑。游戏包在场景启动前写入文件系统并释放下载缓冲引用。
- 图形上下文丢失、运行时内存错误和引擎退出会显示恢复入口，避免加载罩隐藏后无反馈。不自动无限刷新。
- 不更改 PCK、游戏规则、原存档路径或清空用户存档；续玩沿用游戏已有检查点，并非保存崩溃瞬间的战斗。
- 页面重载仍需重新初始化 Godot 和解压资源；本次解决重复下载并降低部分内存负担，不宣称消除了 iPhone 的所有闪退。
- 只读诊断：`window.dearthRecovery` 包含版本、缓存/网络字节数及缓存可用状态；本地仅记录中断时间/状态，不上传遥测。
- 验证脚本 `qa/recovery/recovery.cjs`：全新加载、缓存重进、离线重进、真实 UI 存档续玩、单片损坏修复、第一夜结算、上下文丢失恢复入口及旋转/安全区几何。真机 Safari 长时间游玩仍待验收。

实际结果：Chromium 全套通过；WebKit 在线重进/续玩/单片修复/战斗/比例测试通过，模拟离线导航遇到 Playwright 内部错误，因此不标记 WebKit 离线已通过。

### 启动阻塞修复（v6；覆盖上面的 v5 离线能力说明）

用户随后反馈 Safari 进度卡住、没有有效提示；尚未取得卡住时的 MB 数字及真机日志，不能把实际原因认定为缓存。

本轮复现的代码缺陷：v5 对 Cache Storage 打开、读取、写入无限等待。模拟缓存无响应后，v5 无资源请求且按钮保持禁用；v6 最长约 1.8 秒即绕过对应缓存继续下载。读取异常/存储受限不再阻止进入。

- 离线 Worker 改成纯网络转发，不在 HTML/脚本请求前等待 Cache Storage；旧 v5 控制器可升级。v6 不再承诺断网启动。
- 保留分片缓存作为尽力而为的优化。WebKit 临时上下文在本轮无离线壳的条件下未保留缓存内容，重进下载了完整资源；**撤回对 v6 的“重进必定零下载”承诺**，优先验证进入和续玩。原 v5 的零下载证据只适用于 v5。
- 加入「卡住了？兼容模式进入」，`?safe=1` 彻底跳过资源缓存；不删除缓存和 IndexedDB 存档。
- HTML 内置启动状态/错误处理，外部引擎或加载器文件失败时也能显示重试入口；15 秒脚本等待提示，资源下载 90 秒超时，分片最多重试一次。
- 显示资源清单、引擎、游戏内容、手机界面、场景启动等阶段。保留 v5 手机渲染减负与原比例同步。
- 证据：`qa/startup-v6/` 的缓存故障注入、脚本下载失败、旧 Worker 迁移及真实 UI 启动/续玩/首夜测试。未完成用户 iPhone 真机验证，不能保证已消除所有卡死/闪退。
